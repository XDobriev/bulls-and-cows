# Архитектурная документация: Bulls and Cows

## 1. Структуры данных и алгоритмы

### Состояние игры (`GameState`)

Игровое состояние хранится в едином неизменяемом объекте `GameState` (`src/core/gameState.ts`), типизированном через TypeScript:

```ts
export interface GameState {
  readonly settings: GameSettings;
  readonly secret: string;
  readonly status: 'idle' | 'playing' | 'won';
  readonly history: readonly TurnRecord[];
  readonly startTime: number | null;
  readonly endTime: number | null;
}
```

- **Почему выбран такой подход**: Объект состояния содержит модификатор `readonly` для всех полей. Любое изменение состояния выполняется чистыми функциями-редьюсерами (`updateSettings`, `startGame`, `submitGuess`, `resetGame`), возвращающими новый объект состояния через деструктуризацию (spread-синтаксис `...state`). Это исключает неожиданные побочные эффекты (side effects), предотвращает рассинхронизацию интерфейса и упрощает отладку и тестирование.

### История попыток (`TurnRecord[]`)

История хранится как неизменяемый массив объектов `TurnRecord`:

```ts
export interface TurnRecord {
  readonly attemptNumber: number;
  readonly guess: string;
  readonly bulls: number;
  readonly cows: number;
  readonly timestamp: number;
}
```

- **Иммутабельное добавление**: Каждая новая попытка добавляется в историю через создание нового массива `history: [...state.history, newTurn]` без применения мутирующего метода `Array.prototype.push`.
- **Защита от дубликатов**: Перед фиксацией хода состояние проверяется функцией `state.history.some(...)`. В случае повтора запись в историю не добавляется, счётчик попыток не увеличивается, а пользователю возвращается информативное уведомление.

### Алгоритм `evaluateGuess`

Реализован в `src/core/evaluateGuess.ts` исключительно через функции высшего порядка и методы массивов (`filter`, `includes`), без императивных циклов `for`/`while` со счётчиками-аккумуляторами:

1. Обе строки (`secret` и `guess`) приводятся к нижнему регистру через `toLowerCase()` для единообразной обработки шестнадцатеричных цифр (`A`–`F` и `a`–`f`).
2. Строки преобразуются в массивы символов с помощью `Array.from()`.
3. Подсчёт **быков (bulls)**: количество символов попытки, значение которых строго совпадает со значением в секрете на том же индексе (`char === normalizedSecret[index]`).
4. Подсчёт **коров (cows)**: количество символов попытки, значение которых не совпадает на текущем индексе (`char !== normalizedSecret[index]`), но символ присутствует в секрете (`normalizedSecret.includes(char)`).

### Алгоритм `countPossibleSecrets`

Реализован в `src/core/countPossibleSecrets.ts` рекурсивно и мемоизирован:

1. Задача нахождения количества секретных чисел длины $L$ в системе счисления с основанием $B$ эквивалентна вычислению числа размещений без повторений (перестановок) $P(B, L) = \frac{B!}{(B - L)!}$. Так как лидирующий ноль разрешён (например, секрет `0123`), вычитать варианты с нулём в начале не требуется.
2. Базовые случаи рекурсии:
   - Если $L < 0$, $B < 0$ или $L > B$, возвращается `0`.
   - Если $L = 0$, возвращается `1` (существует 1 пустое размещение).
3. Рекурсивный шаг: `base * countPossibleSecrets(length - 1, base - 1)`.
4. Мемоизация: функция высшего порядка `memoize` оборачивает рекурсивное вычисление и кэширует результаты в структуре `Map<string, number>`. Поскольку рекурсивный вызов обращается к самой мемоизированной функции, все промежуточные подзадачи сохраняются в кэше, исключая повторные вычисления при каждом открытии настроек.

## 2. Анализ сложности (Big O)

Обозначения: $L$ — длина секретного числа ($L \in [2, 6]$), $B$ — основание системы счисления ($B \in \{2, 8, 10, 16\}$).

| Функция                                | Время (Time Complexity)          | Память (Space Complexity)        | Обоснование                                                                                                                                                                                                                                                                                                                                                                           |
| -------------------------------------- | -------------------------------- | -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `generateSecret(length, base, random)` | $O(L \cdot B)$                   | $O(B)$                           | Формирование исходного массива алфавита занимает $O(B)$. Рекурсивная процедура `pickDigits` делает $L$ шагов; на каждом шаге фильтрация оставшихся цифр массива занимает $O(B)$ времени. При фиксированных ограничениях игры ($B \le 16$, $L \le 6$) выполняется не более 96 операций, что эквивалентно $O(1)$. Стек вызовов и результирующий массив требуют $O(B)$ памяти.           |
| `evaluateGuess(secret, guess)`         | $O(L^2)$                         | $O(L)$                           | Нормализация и создание массивов символов занимают $O(L)$. Метод `filter` проходит по массиву длины $L$; внутри для каждой коровы метод `includes` выполняет линейный поиск по массиву длины $L$, давая в худшем случае $L \times L = L^2$ операций. При $L \le 6$ это не более 36 операций ($O(1)$ на практике). Дополнительная память отводится под два массива символов длины $L$. |
| `isValidGuess(guess, length, base)`    | $O(B + L)$                       | $O(B + L)$                       | Создание фабрики `createDigitValidator` формирует `Set` из $B$ допустимых символов за $O(B)$. Проверка каждого символа попытки через `every` и `Set.has` выполняется за $O(1)$ на символ, итого $O(L)$. Проверка уникальности символов через создание `new Set` из строки длины $L$ занимает $O(L)$ времени и памяти. Суммарная сложность линейна по $B + L$.                         |
| `countPossibleSecrets(length, base)`   | $O(L)$ без кэша / $O(1)$ с кэшем | $O(L)$ стек / $O(B \cdot L)$ кэш | При первом вызове выполняется ровно $L$ шагов умножения до базового случая $L = 0$. При повторных вызовах с теми же аргументами `memoize` извлекает результат из хэш-таблицы `Map` за среднее время $O(1)$. Потребление памяти под стек вызовов ограничено глубиной $L$, размер кэша не превышает общего количества возможных пар $(L, B)$.                                           |

## 3. Принципы чистого кода (Clean Code)

В проекте применены фундаментальные принципы чистого кода:

### 1. DRY (Don't Repeat Yourself)

- Каррированная функция-фабрика `createDigitValidator(base)` (`src/core/createDigitValidator.ts`) повторно используется в двух независимых слоях приложения:
  1. В ядре валидации попытки `isValidGuess` (`src/core/isValidGuess.ts`).
  2. В UI-слое ввода в реальном времени (`src/ui/components/gameView.ts`) при обработке событий `beforeinput` и фильтрации вставки из буфера обмена.
- Универсальная функция высшего порядка `memoize` (`src/core/countPossibleSecrets.ts`) вынесена в отдельную абстракцию, изолируя логику кэширования от математического алгоритма.

### 2. KISS (Keep It Simple, Stupid)

- Алгоритм `evaluateGuess` (`src/core/evaluateGuess.ts`) сформулирован декларативно через методы массивов в 15 строк кода без громоздких вложенных циклов, флагов и ручных счётчиков.

### 3. Единственная ответственность (Single Responsibility Principle)

- Каждая функция ядра решает строго одну задачу:
  - `generateSecret.ts` — генерация случайной уникальной последовательности;
  - `evaluateGuess.ts` — подсчёт быков и коров;
  - `createDigitValidator.ts` — проверка принадлежности символа алфавиту;
  - `isValidGuess.ts` — комплексная валидация попытки;
  - `countPossibleSecrets.ts` — комбинаторный расчёт;
  - `leaderboard.ts` — сортировка, сохранение и форматирование рекордов;
  - `domUtils.ts` — безопасное создание элементов DOM без `innerHTML`.
- Ядро игры (`src/core/`) полностью отделено от браузерного API и DOM: все 7 тестовых наборов выполняются в изолированном Node.js окружении без браузера.

### 4. Неизменяемость и чистота функций (Immutability & Pure Functions)

- Функции ядра не мутируют внешние переменные и входные параметры.
- `generateSecret` принимает генератор случайных чисел `random` в качестве параметра со значением по умолчанию `Math.random`. Это позволяет передавать детерминированный генератор в юнит-тестах, превращая случайный процесс в проверяемую чистую функцию.
- Состояние игры обновляется через создание новых структур (`src/core/gameState.ts`): `history: [...state.history, newTurn]`.

### 5. Говорящие имена (Intention-Revealing Names)

- Идентификаторы в коде однозначно отражают предметную область игры: `bulls`, `cows`, `attemptNumber`, `TurnRecord`, `countPossibleSecrets`, `GameSettings`, `ScoreEntry`.

### 6. Защитное программирование и Fail-Fast

- Проверка граничных условий на входе: функции `generateSecret`, `createDigitValidator` и `countPossibleSecrets` сразу валидируют допустимость основания системы ($2 \le base \le 16$) и длины, выбрасывая информативные ошибки при некорректных аргументах.
